# DeviceSocket 协议调试工具

这是一个基于 .NET 8 和 Avalonia 的 Windows 桌面调试工具。它与压测工具分离，当前用于单连接验证 Q/GDW 376.1-2012 和 DL/T 645-2007 指令生成、发送和响应解析。

## 启动

在仓库根目录执行：

```powershell
dotnet run --project tools\DeviceSocket.Debugger\DeviceSocket.Debugger.csproj
```

或发布 Windows x64 自包含版本：

```powershell
dotnet publish tools\DeviceSocket.Debugger\DeviceSocket.Debugger.csproj `
  -c Release -r win-x64 --self-contained true
```

启动后先在右侧选择指令，按需修改参数；协议和默认端口会随指令切换。建立 TCP 连接后点击“发送指令”，界面会自动切换到接收页。

### 376.1 定时心跳

选择“心跳”指令后，参数区下方会出现定时发送配置。间隔默认 `120` 秒，可修改后点击“启动定时发送”；每个周期会自动使用启动时保存的参数和当前时间生成 AFN=02H/F3 心跳并发送。启动后切换 376.1 指令或发送其他指令不会停止定时器；手动断开连接、点击“停止”、切换到其他协议或关闭窗口会结束定时发送。

### 接收中心

接收页默认打开“业务回复”分类，高频心跳、异常和连接状态分别进入独立分类，避免心跳确认持续挤占业务排障视图：

- 点击“业务回复”“心跳”“异常/状态”或“全部”切换分类，各按钮显示当前缓存数量。
- 使用搜索框按设备编号、标题、HEX 或解析内容检索，使用右侧下拉框按 AFN/FN、645 功能码或数据标识筛选。
- 列表采用两行紧凑摘要；选中记录后，右侧固定详情区显示完整 HEX、解析结果和请求回复匹配耗时。
- “暂停刷新”只暂停界面消费，TCP 接收和文件日志继续运行；恢复后每 `100` 毫秒批量追加最多 `250` 条。
- 接收中心最多保留最近 `10,000` 条、约 `5,000,000` 个字符，其中心跳最多保留最近 `1,000` 条；界面淘汰不会删除已经写入的日志文件。
- “清空当前”只清理当前分类，“清空全部”同时清理全部分类和等待刷新队列。

### 抄读回复按下发报文回填

选择“抄读回复（AFN=0CH/F129）”指令后，参数区下方会出现“根据下发报文回填参数”输入框。粘贴主站下发的 AFN=0CH/F129 报文并点击“解析并回填”，工具会解析：

- 行政区划码和终端地址
- 主站地址 MSA 与群地址标志
- 回复序号 RSEQ
- 测量点 PN

回填后仍可手动调整各项参数，再点击“生成报文”或“发送指令”。

发送、接收、连接状态和解析错误会写入：

```text
%LOCALAPPDATA%\DeviceSocket\Debugger\Logs
```

## 指令集

内置示例位于 `CommandSets`：

- `QGdw3761/basic-commands.json`：登录、心跳、退出登录、抄读回复（AFN=0CH/F129）和自定义 HEX。
- `Dlt645/basic-commands.json`：读取通信地址、读取数据、自定义 645 帧和自定义 HEX。

工具启动时自动加载随程序发布的指令集，也可以通过“打开 JSON”临时加载其他文件。修改文件后点击“重新加载”即可生效。

一条指令支持三种模式：

- `layout`：按字段顺序声明固定值、输入值、复制、长度和校验和，不需要编写 C#。
- `codec`：调用安全白名单中的协议编码器，自动计算地址字节序、长度、数据域变换和校验和。
- `raw`：替换 `{{参数名}}` 后直接发送 HEX，适合复现已有现场报文。

`fixedValues` 用于指令固定参数，不在界面显示；`inputs` 会自动生成输入框或下拉框。当前白名单编码器为：

- `qgdw3761.link`
- `qgdw3761.gatherReadingResponse`
- `dlt645.frame`

完整字段约束见 [debugger-command-set.schema.json](../../docs/debugger-command-set.schema.json)。

## 错误处理

- JSON 语法或语义错误只会阻止对应文件加载。
- 参数或 HEX 错误会显示在接收页，不会发送数据。
- 半包会继续缓存，粘包会逐帧解析。
- 非法帧保留原始 HEX 和协议错误原因，后续帧仍继续处理。
- 接收缓冲超过 1 MiB 时会记录尾部数据并重置，避免异常输入持续占用内存。
